# 构造与发送失败边界复核

版本保持 2.0.0，DLL/SYS 数值版本保持 2.0.0.0。本轮基线为
`9dc04c7344b38f556fd51f4a12a96f12d7f1c6a515e440cefaf3ac4a41d724dd`，
完整 612 个源文件快照位于 `out/lifetime-edge-baseline/9dc04c7344b3`。

本轮确认并修复一处发送失败诊断的归属错误：同一 NBL 的后续 NB 在读取
前缀时失败，会沿用前一个 NB 的队列号和 Ethernet 偏移。每个 NB 开始时
现在重置这两个字段，使未分类的失败项记录为 UNKNOWN 队列和偏移 0。
该问题未表现为槽位漏还或错误数据发布；导出接口、同步和卸载门控保持不变。

## 跨 MDL 的发送描述失败

以前实际 Read 和实际 Describe 分别在不同宿主中验证；新增测试连接实际
Read、Describe、Send 和回收路径。发送链包含合法前缀、部分复制后失败的
报文和后续合法报文。失败项不能发布，已保留槽位必须归还，之后必须能用
新的 generation 合法复用。完整包的字节内容、发布次序、唯一 token、回收
和池状态分别核对，避免只检查最终计数。

错误记录还逐项核对当前 NB 的长度、队列、偏移、状态和拒绝原因。旧源码
在完整清理后返回专用失败码 135，直接证明错误字段来自前一 NB；修复版本
必须通过同样的输入。历史审计使用 `send-diagnostic-ledger.ps1` 对完整旧、
新文件及唯一已审修复作精确比对，拒绝无关改动，保留历史基线原始内容。

测试包括 IPv4/IPv6、1/2/8 队列及旧、新 NDIS 能力边界。NDIS 6.20 的普通
报文路径不能读取较新的卸载元数据。MDL 映射与 NDIS 对象仍是宿主边界，
源码提取、有限适配及单处负控记录在审计产物中。负控保留漏还的真实 token
直到观察完成，再用实际池转换补偿并执行回收；正常构建没有补偿。

## 启动策略尚未完成时的所有权

Open 的初始策略请求可以在注册后阻塞。构造线程仍持有会话、设备、映射、
事件和模块引用，并占用运行时额度；此时诊断枚举不能取得尚未发布的会话。
新增回归让真实诊断线程在这个边界取样，随后允许策略成功或失败。

成功才可以发布会话；失败必须保存原始错误并完成实际清理，不能残留准入、
映射、堆、工作项、线程池或模块引用。所有测试创建的线程都在其拥有资源
释放之前汇合。测试没有为诊断额外 Retain 构造中的会话，也没有把未返回的
私有指针当作公开会话句柄调用。

## 旧系统环境探测

逐字提取实际 EnvInit，表驱动验证系统版本与架构探测的回退。kernel32 是
借用的模块句柄；缺少 IsWow64Process2 或调用失败时，保留的 MAYBE_WOW64
源码分支必须使用旧 API 回退。测试分别编译带与不带该分支的构建，不能将
该分支的覆盖解释为当前 x64 发布流程已经启用了跨架构构建。

环境探测测试不创建线程、堆块或自有模块引用。API 调用账本验证控制流与
借用关系，不代替旧系统加载和运行验收。新系统能力继续由现有运行时 NDIS
门控和实际卸载测试覆盖。

## 重放与验收范围

```powershell
pwsh -NoProfile -File tools/audit/verify-send-describe.ps1
pwsh -NoProfile -File tools/build/validate-unified.ps1
```

普通与守护内存验收包含新增发送和启动边界回归，以及环境探测的两种编译
分支。定向矩阵覆盖 ISO/MS volatile；编译负控验证指纹及测试分支护栏。
完整验收和精确资源范围记录在
`out/lifetime-edge-investigation/final-review.json`。历史证据保留原始指纹，
不标为本轮重跑。

Windows 事件、锁、等待及测试拥有的线程实际执行；内核 DDI、NDIS、IOCTL
及 IRQL 仍由宿主边界提供。生产变更仅在每个 NB 开始时重置两个诊断字段，
没有增加锁、分配、线程或轮询。唤醒次数和宿主资源账本不代表实机内核
CPU、池或泄漏测量。
真实旧系统、Driver Verifier、挂起恢复、设备移除和长期资源及 CPU 验收
仍待专用系统完成。证据保持 `kernel_runtime_tested=false` 和
`production_ready=false`。
