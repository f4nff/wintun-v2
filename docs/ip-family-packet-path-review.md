版本保持 2.0.0，DLL/SYS 数值版本为 2.0.0.0。基线为
`e9e18f1bacc485b39643e9f4aa1dcf9cf1f5319d467b1bbe3920b93c255c5540`，

## 分族入口与结果

SYS 和旧接口模型使用 `PB_TEST_IP_VERSION=4` 或 `6` 分别编译，每个进程
只执行对应地址族，并写出 FAMILY 见证和逐包类型。每个进程独立预热、
计数及核对句柄差值。0 保留原有混合回归入口及历史命令行为，不用于分族
结果汇总。非法值必须编译失败；把已正常运行的另一个地址族日志送入审计
必须失败，不能只更换结果标签。

| 定向组（ISO/MS × 普通/守护） | IPv4 | IPv6 |
| --- | --- | --- |
| SYS 普通 Send / Receive | 256 / 16 场景，8 进程 | 256 / 16 场景，8 进程 |
| SYS 128 KiB 发送预算及准入边界 | 384 场景，4 进程 | 384 场景，4 进程 |
| SYS 合并缓冲区 / Drain / Fault | 96 场景，4 进程，32 次实际线程汇合 | 96 场景，4 进程，32 次实际线程汇合 |
| 旧接口双向 32 包 / 自然部分预留 | 64 / 192 场景，8 进程 | 64 / 192 场景，8 进程 |
| Rust 独立 family 测试入口 | 5 项 | 5 项 |
| C 分段 / 选项 / 分片 Python 入口 | 3 项 | 3 项 |

上述模型场景数包含一半经过检查的预热场景。Rust 与 Python 的每个地址族
也分别在独立进程执行，原完整 workspace 与通用回归继续运行。新增永久
DLL 构建/审计入口接入 Safety 和 UnifiedTests，避免依赖临时探针脚本。

## 发现的覆盖缺口

旧 partial32 测试原来固定生成 IPv4 TCP。现在分族入口将实际 IP 版本和
TCP/UDP 类型传入种子及目标包生成器：每族测试 k=1/7/31 个空槽、完成后
恢复或停止、普通及回绕。原实际门闩、Reserve/Commit 向量、一次载荷复制、
Head 前缀、槽位代数和线程/资源归还断言保留。默认0仍维持原 IPv4 TCP 的
24 场景语义及旧 full32 的32场景，不将历史计数改标成新覆盖。

SYS 三组模型保留相同真实函数、旧宿主及所有权检查，分别执行每个地址族。
发送 32 包的预算向量仍为 32、31+1、16 次各2个；跨队列拆批单独记录。
合并接收仍检查每轮16个描述符、两个缓冲区的真实 Busy 归还、停止后的
后缀取消及最后 Active / FaultQuiesced 的两种顺序。原生日志、超时预算与
数据包没有共用发送时间字段；生产时钟及协议实现均未改动。

## 地址族的协议边界

新 Python 用例使用独立校验和 oracle，并逐字检查源缓冲区、输出载荷、
未写区域、元数据长度和时间戳字段。IPv4 覆盖20字节 NOP 选项与 TCP
Timestamp 的组合；IPv6 TCP 覆盖8字节 Hop-by-Hop 扩展与 Timestamp。
每次实际 checked 调用写出32段，TSval/TSecr 保持不透明原字节，载荷包含
独立的序号和两种64位标记，均不转换为日志或提交时间。

每族另构造32个1500字节 TCP 选项/扩展报文，验证严格 RSC 不接纳这些
边界且不修改待合并状态及输出。每个协议还构造32个真实首分片形状：从
已校验的较大数据报中保留1024字节、以8字节为单位的分片数据，设置 IPv4
MF 或 IPv6 Fragment/M 位，保留完整数据报的传输层长度和校验和。GSO
解析必须拒绝，checked 写出不得生成任何前缀或修改源、哨兵及输出长度。

IPv6 UDP 携带扩展头时，当前 USO 分段策略明确返回 UNSUPPORTED；分别
验证32个输入。它不构成已确认的兼容性故障，普通包路径及协议能力选择
保持不变。测试不把协议头中的 TCP 时间戳当作发送调度时钟。

## 验收边界

本轮修正分族覆盖及验收入口，没有确认新的生产路径缺陷。DLL 仍提供旧
Wintun 接口，SYS 仍统一使用 v2，卸载及新系统能力选择未改动。源码冻结
后执行完整主测试、守护内存、分族定向审计、编译负对照、静态诊断对比及
PE 导出/导入、版本检查；历史证据保留各自原始指纹。

句柄、槽位、NBL/MDL、引用及实际测试线程的平衡只适用于对应 hosted
边界。普通收包的 partial MDL 引用与可选 RSC/URO 的私有快照/前瞻复制
分开计数；操作计数不表示真实 CPU、吞吐或长期内核泄漏验收。旧系统实机、
NDIS/IRQL、Driver Verifier 和持续压力测试仍需目标机器验证。
