# SYS 按需读取发送分类前缀

起始源码指纹为 `20cca9f9cce19958cac480fd34cd07e71609da06a018f60a138c93af4f4c7919`，完整快照位于 `out/sys-send-prefix-baseline/20cca9f9cce1`。

## 问题与修正

Send 原先在每个 NET_BUFFER 上预读最多 128 字节，用于以太网分类、直接 IPv6 邻居消息识别和地址散列队列选择。普通 IP 随后的 Describe 还会完整读取 IP 数据。这使普通包重复读取了并不参与分类的内容，分散 MDL 时也可能重复请求后续 MDL 的系统地址。

`PB_ETH_CLASSIFY_MAX` 明确当前分类需要的上限：一个带 VLAN 的 18 字节以太网头、40 字节 IPv6 基本头及首个载荷字节，共 59 字节。这覆盖 Inspect、直接邻居消息类型，以及当前只使用 IP 地址的 SelectQueue。未来扩大 VLAN、控制回复或散列字段时，需要一起更新这个边界和测试。

当前先读取最多 59 字节；只有既有控制候选分支才补读至原来的 `min(NET_BUFFER_DATA_LENGTH,128)`，保留已经复制的分类字节。普通 IP 的完整 Describe、校验和、卸载策略、字节预算、发布和引用计数不变。前缀不授权 NDIS 元数据或跳过整包读取。

`PbV2Read` 的原函数体原样移入 `session_read.h`，供实际驱动和测试共同使用。它不缓存 MDL 或系统地址；失败可能留下部分输出，调用方必须丢弃。本次对照脚本验证提取前后函数体完全一致。

## 成本与取舍

1500 字节普通帧的前缀复制由 128 降至 59 字节，完整 IP 复制不变。测试的 40/24/余下数据分散布局还包含非零当前偏移和一个空 MDL：前缀映射调用从三次降为两次，整包读取仍为三次。映射收益依赖实际布局，不能据此宣称固定 CPU 或吞吐提升。

控制报文总读取字节数保持不变，但补读会多一次调用并重新遍历链；在测试的 ARP/NDP 布局中多一次映射。控制输入仍被限制在原来的 128 字节内。这个取舍把额外工作限定在已有控制分支，没有引入跨调用的游标或映射缓存。

## 所有权、失败与验证

每次发送的 TransitionLock 窗口、尝试和字节预算保持不变，预读或补读不会另计一次发送尝试。队列锁、private token 校验、发送完成及 Returns rundown 的范围不变；控制回复继续在释放锁后上调，并由原 send 引用保护整个回调。

普通帧的后续 MDL 映射失败可能从预读阶段移到 Describe 阶段。此时刚保留的槽必须回滚到 FREE，不能发布描述符。补读失败同样不进入控制解析或回复。测试覆盖这两条路径，并确认完成调用、Active、rundown、槽状态和句柄数量平衡。

`send_window_tests.c` 继续执行原有窗口/预算、队列切换、pause/detach/fault、回收错误、发布失败、同步重入及完成后禁止访问 NBL 的回归。新增用例使用独立、只读、带保护页的 MDL 映射，运行实际 Send、Read、Ethernet Inspect/Control 和 SelectQueue。Describe 的宿主替身使用实际 Read 完整复制数据，并逐字节比较已发布的 IP 内容。实际 Describe 自身仍由既有独立测试和完整验收覆盖。

新增用例覆盖 IPv4/IPv6 TCP/UDP、VLAN、1/2/3/8 队列、短包及 59/64/128 边界，精确 ARP/NDP 回复和丢弃、映射失败、偏移错误，以及 2412 个带保护页的 reader 范围/skip 组合。普通和 Safety 的既有 Send 入口都会执行。`verify-sys-send-prefix.ps1` 在两种 MSVC volatile 模式下对照冻结/当前 Send，并记录字节数、映射数、源码/二进制指纹和真实退出码。

事件策略、worker 等待、预算续跑、满环唤醒、排空边界和清理屏障没有修改，完整离线验收会继续运行这些回归。SYS 未加载；真实 IRQL、Verifier、ETW/WPA、CPU、吞吐、延迟、低资源和长稳仍需内核验收。
