# 普通队列消费的无效字节计费

版本保持 `2.0.0`，PE 数值版本保持 `2.0.0.0`。起始源码指纹为 `5788103200a3e5280439af348fe576f2c32c4f9faf5fc7cac09fa9b51c81a2e8`；原共享核心保存在 `out/queue-pop-baseline/5788103200a3/common`，其中 `v2_core.c` SHA256 为 `c0ed6bf51fd890b27667254839ac6886f365acf9a198ce406a0a0f8748995914`。

## 已确认的成本

DLL 的 `ReceiveBatch` 和 `PollInternal` 通过 `PbQueuePop` 读取完整描述符。旧实现调用 `PbQueuePopBudget(..., UINT32_MAX, ...)`；原生 x64 `/O2` 代码仍为每项提取 Length、钳制到 65536、累计字节并比较剩余预算。这不影响正确性，但普通消费不需要这些操作。

一批最多 32 项，每项最多计费 65536 字节，总计最多 2097152，永远达不到 UINT32_MAX。普通消费因此只应受请求项数和实际可用项数限制。增加兼容 WDK 默认 C 模式的编译期断言，确保未来调整批次或块大小时仍满足这个等价条件。

## 修正边界

将原有消费实现收敛到一个强制内联的私有 `PopDescriptors`，两个公共入口分别提供常量 `budgeted=0/1`。普通入口在编译时去掉逐项字节计费；带预算入口保留从本地描述符快照计算费用的既有规则。没有复制两套游标校验、共享读取或发布实现，也没有运行时模式、缓存或额外线程。

| 路径 | 保留的约束 |
| --- | --- |
| DLL 普通 ReceiveBatch / PollInternal | 请求最多 32 项；校验 producer 范围和单调进度；复制完整描述符后一次发布 Consumer |
| SYS RX_SUBMIT | 继续使用 `PbQueuePopBudget`，最多 32 项或 128 KiB；非法超长 Length 仍只按一个块计费；计费和返回内容来自同一份快照 |
| SYS TX_RECYCLE | 继续使用既有 token-only 消费及逐项所有权校验；错误 token 的有效前缀可退休，随后故障并停止事务 |
| 槽位退休 | DLL 仍整批校验后才变更私有池；FREE、代次和空闲索引由原有核心函数维护 |
| 完成消费唤醒 | 每次成功非空消费后仍设置 KernelEvent；消费前未满的快照无法排除生产者随后填满并等待的竞态，Armed 只承担数据通知 |
| 内核归还唤醒 | 保留 RxLock 下确认的 credit full → usable 通知、满完成环消费者通知和 Flush 预算 continuation |
| 关闭与内核回收 | 保留用户 lease、真实 STOPPED/Active 确认、设备关闭屏障，以及 worker join、AllReturned、Returns rundown 后才释放 MDL/映射的规则 |

共享布局、函数表、协议、ABI 和事件策略均未改变。普通消费的快照不根据 Length 做决定，恶意或损坏的描述符仍由后续完整描述符及 token 校验拒绝。

## 验证

新增 `tests/model/queue_pop_tests.c`，直接包含实际核心，通过独立前缀计算核对结果。修改前后分别在 `/volatile:iso` 和 `/volatile:ms` 下运行，每次执行 45312 组矩阵：

- 只读源页、紧贴保护页的输出；1/2/4/8/32/64/4096 容量、请求 1～32 项、空环和部分读取、物理环及 uint64 游标回绕。
- Length 为 0、1、20、块边界、超过块大小和 UINT32_MAX；普通消费与 64 KiB、128 KiB、UINT32_MAX 字节预算的精确前缀。
- 无效参数、过小预算及损坏游标在源和输出都不可访问时仍不能读写或发布。
- Consumer 发布前核对输出完整；发布后立即覆写源项，核对返回内容不变。

`verify-queue-pop.ps1` 固定旧核心哈希，使用相同当前 DLL 和宿主内核函数执行 A/B。除矩阵外，运行真实 arm/recheck 并发、完成 Flush、暂停/排空归还和 credit 唤醒边界、DLL API 与完成退休测试。普通消费的原生指令已不含块大小计费，带预算消费仍保留该计费；源代码注释不作为机器指令证据。新矩阵也接入常规 Tests 和保护页 Safety。

## 成本测量及限制

复用实际 DLL reserve → commit → 宿主提交读取 → 完成发布 → poll 循环，保留真实 Windows 事件调用。宿主提交读取改用与实际 SYS 一致的 128 KiB 带预算入口，因此计时循环里只有实际 DLL 完成读取使用普通消费，避免把宿主 peer 的优化计入 DLL 收益。数据包长度固定为 20，不触及提交预算。

初次完整定向 A/B 证据为 `out/queue-pop/c26e65f16bb7/evidence.json`；同一允许 CPU、每组预热 2000 次、计时 100000 次，七轮交替次序中位数如下：

| 顺序 | 批量 | 修改前 ns/批 | 修改后 ns/批 |
| --- | ---: | ---: | ---: |
| 顺序完成 | 1 | 238.64 | 239.66 |
| 顺序完成 | 8 | 393.92 | 387.95 |
| 顺序完成 | 32 | 916.11 | 905.10 |
| 逆序完成 | 1 | 242.99 | 242.31 |
| 逆序完成 | 8 | 392.37 | 387.36 |
| 逆序完成 | 32 | 917.98 | 893.79 |

32 项时每次普通消费确定性减少 32 次无效计费，整个 DLL 循环的测量差异约为 1%～3%；小批量没有稳定加速承诺。这些数据不代表内核 CPU、吞吐或延迟。维护收益在于明确区分两种既有消费语义，同时共同维护发布和校验规则。
