## 时间字段与协议边界

PB_DESCRIPTOR、PB_LEASE 和分段计划没有发送时间或发送调度字段。
Epoch 表示会话身份，Generation 表示槽位代数，均不能用作时间。
旧 Wintun 的 SendPacket 表示提交，并不保证返回时已经发送到网络。

| 来源 | 用途 | 本轮检查 |
| --- | --- | --- |
| NtQuerySystemTime | 日志时间，1601 UTC 起的 100 ns | 不参与包提交、序号或停机期限计算 |
| GetTickCount64 | DLL 控制任务、等待及停机预算 | 起止值使用同一毫秒时钟 |
| KeQueryInterruptTime / 10000 | SYS 排空期限 | 内核内部毫秒比较，不与 DLL 绝对时间交换 |
| Rust fallback 的 now/deadline | 模型内的排空状态机 | 同一调用方时钟，使用回绕差值 |
| TCP TSval/TSecr | 报文中的不透明 TCP 选项 | 不解释为上述任何时钟，也不更换为提交时间 |

新增 Python 测试将一个包含 TCP Timestamp 选项的对象通过一次实际
PbWriteSegmentBatchChecked 调用写成 32 段，覆盖 IPv4/IPv6、零值、最高位
及接近回绕的字段。逐段验证选项、序号、两个独立 64 位载荷标记、载荷和
独立校验和，源缓冲区保持不变。另对每种 IP 版本构造 32 个合法的
1500 字节 TCP 包，分别改变 TSval/TSecr；实际 CoalesceBegin/Append
必须拒绝带选项对象，且不修改状态或输出。当前严格 RSC 不接纳 TCP
选项，因此不能把不同包的时间戳误合并为同一组头部。

## 批量与复制的计数边界

SYS Send 是协议栈发往 TUN 用户态的方向；用户态 Commit 经 SYS Receive
注入协议栈。旧接口中的应用 Send/Receive 使用相反的观察视角。
测试明确记录方向和包序号，不依赖名称猜测数据流。

| 路径 | 全部 32 包就绪时的预期 | 载荷复制边界 |
| --- | --- | --- |
| 旧接口应用 Send → v2 Commit | 一次 Reserve(32)、一次 Commit(32) | 旧字节 ring 到原生槽位每包一次 |
| v2 Receive → 旧接口应用 Receive | 一次非空 Receive、一次 Release(32) | 原生槽位到旧字节 ring 每包一次 |
| Rust 原生普通包 | 一次 Reserve/Commit 或 Receive/Release | data_mut/data 直接借用共享载荷；Lease 向量只复制元数据 |
| Rust GSO/USO → wire 输出 | 一次 checked 批量 FFI，32 个输出 | 头部和分段载荷直接写最终输出，没有中间整包缓冲区 |
| SYS 普通同队列 Send，32 × 1500 字节 IP | 一次发布 32 描述符 | 每包读取 59 字节分类前缀，另复制一次 1500 字节 IP 载荷 |
| SYS 普通 Receive，32 × 1500 字节 IP | 一次取出并指示一条 32 NBL 链 | partial MDL 引用共享载荷；40 字节检查前缀和描述符复制单独计数 |

旧 ABI 允许调用方保留独立字节 ring 中的指针，原生 ABI 则以槽位 lease
管理生命周期。桥接的每方向一次载荷复制维持这两个所有权约定；不能
直接让旧指针指向可能被原生回收重用的槽位。

32 包测试计数只限定准备好的非空批次，不把空 Poll、条件事件或 SDK
回调次数当作数据包数。真实事件可以合并或重复提示。回绕、逆序发布及
逆序归还使用各自的正常所有权路径，清理前归还全部 token、NBL/MDL、
引用和 credit，并汇合测试创建的线程。

## 合法拆批与额外复制

512 KiB 的旧接口单轮预算会将 32 × 65535 字节拆为四轮，每轮八包；
这不是逐包 Commit。SYS Send 的字节和尝试预算同样保持有界。不同队列
交替时，当前单队列窗口会在换队列时发布；32 个交替队列包可能得到
32 次单项发布。这一行为需要与同队列退化区分。跨队列累积涉及锁顺序、
同流顺序及内核栈预算，本轮不在缺少并发收益证据时重设计该路径。

同一组普通 Send 测试分别使用宿主 NDIS 6.20、6.89 能力变量。旧版本
不得读取未来 USO 元数据槽位，批量和复制预期保持相同。这是版本分支
测试，不等于在 Windows 7 或 Windows 11 上运行了真实网络栈。

可选 RSC/URO 先把共享载荷取到私有快照，再构造合并对象，存在额外复制。
它保护解析及合并免受共享区并发修改，并非默认普通包路径的重复复制。
checked 分段入口也会重新验证当前源包，不能为了减少解析而绕过校验。
历史快照及合并成本测试继续保留。

## 验收范围

本轮确认并修复了历史 `verify-sys-return-wake.ps1` 的构建遗漏：拼接旧
Return 与当前 Receive 函数时，从函数签名截取会丢失 `platform_nbl.h`
依赖，导致 PB_NBL_SET 未定义、基线模型编译失败。现在在拼接头中显式
包含实际平台头，并记录其哈希和原函数区间；两个函数的原文保持不变。
修复前的脚本、合成头和编译失败证据单独保存。普通/守护内存下的旧/新
Return、等待路径八个进程继续保留，旧版与当前唤醒次数的对照仍成立。
这项修复影响离线审计的可重放性，不改变 SYS/DLL 的运行行为。

新增回归先执行现有实现，再检查实际调用向量、复制量和所有权；本轮
没有据此确认新的生产路径缺陷，因此没有改动生产代码、协议、导出或
系统能力选择。SYS 测试在 hosted 模型中执行实际生产函数，不能替代
真实 NDIS、IRQL、Driver Verifier、旧系统安装和长期压力测试。

ISO/MS volatile、NDEBUG、守护内存及失败编译对照用于防止测试退化。
守护范围按各宿主实际支持的分配记录，不把元数据复制计为载荷复制。
操作计数只能说明路径成本，不能据此宣称真实内核 CPU 或吞吐改善。
