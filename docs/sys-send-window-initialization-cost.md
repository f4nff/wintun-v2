# SYS 发送窗口的批量数组初始化成本

版本保持 `2.0.0`，PE 数值版本保持 `2.0.0.0`。本轮从完整验收指纹 `a659e31c7f2efc8507bed8f56020183ee1eab483113c20cd1c4f7de1b2c29137` 继续检查槽位归还、回收屏障、关闭/唤醒和 CPU 成本。没有新确认的槽位提前复用、内核提前释放或漏唤醒；确认并修正一处发送入口的冗余初始化。

## 编译结果与局部修正

原 `PB_TX_WINDOW` 内嵌 32 个 descriptor 和 32 个 owner 指针。`PbV2Send` 对整个结构做聚合初始化，即使没有任何报文能进入窗口，也会将两个批量数组全部清零。当前 x64 宿主 MSVC `/O2 /volatile:iso` 汇编保留两次 memset，分别为 2,048 和 256 字节，共 2,304 字节/发送调用。已经停止接纳的拒绝路径也承担这项工作；没有会话的早返回发生在初始化之前，不承担它。

数组项实际在成功 Describe 后被完整赋值：先写 `Items[Count]` 和 `Owners[Count]`，最后才增加 Count。发布循环只读取 `[0, Count)`，Count 为零时不读取数组。因此数组的初始零值没有承担所有权、错误回滚或发布授权的职责。

修正只把两个数组改为 `PbV2Send` 的独立调用栈存储，窗口控制结构保存它们的指针。控制结构继续使用完整聚合初始化，新增控制字段仍自然初始化为零。数组、控制结构及原先内嵌数组具有相同的调用生命周期，不创建分配、共享缓存、异步所有者或预分配池。

成功项继续由零初始化的局部 descriptor 完整赋值，owner 继续在 Count 增加前写入。队列切换、预算结束、发布失败和控制回调仍先刷新窗口；NDIS completion 后不再访问 NBL。重入发送使用自己的调用栈数组，不能借用外层发送的存储。没有改变任何锁、原子同步、引用写入、槽位状态、回收、事件、共享布局、导出 ABI 或版本。

这会增加两个私有指针及相应寻址。此次宿主基准的汇编栈预留从 2,992 变为 3,016 字节，不能称为减少栈占用；内核构建、编译器内联及其真实栈使用也不能由该宿主数值代替。选择保留聚合初始化，是为了避免部分清零依赖结构字段顺序，或让未来控制字段漏初始化。

## 回归与填毒存储

`verify-sys-send-init.ps1` 固定旧发送头 SHA256 为 `f73f43a6692348553489866ce3d902165eac91f56adc97644fa2a492eefc7d3b`，位于 `out/sys-send-init-baseline/a659e31c7f2e/driver/v2/session_send.h`。旧/新发送体配合同一当前 recycle/reference/core 和宿主 NDIS fixture 执行全部既有发送回归。

另在忽略的 out 目录生成当前头的填毒副本，只在窗口控制初始化之前，把两个调用栈数组填为 `0xa5`。生产代码没有测试钩子或填毒写入。它与新旧实现分别在 ISO/MS volatile、普通/保护页模式运行，共 12 个正常回归进程。

覆盖包括空/停止/无会话出口、32-attempt/128-KiB 预算、4096 项长链、跨队列切换、满环和满池、迟到归还、有效回收前缀后故障、发布失败、同 NBL 多个 NB、控制回复重入、回调尾部引用、completion 后保护页、实际 MDL 读取边界。填毒副本也必须全部通过，验证实际路径不依赖批量数组的初始零值。原有窗口资源与句柄核对继续执行。

## 宿主测量与取舍

`tests/bench/sys_send_init_bench.c` 复用实际 Send，保留相同 fixture 检查和计数；NDIS/DDI 和 Describe 是宿主替身。每项先预热 2,000 次，再计时 200,000 次，固定到允许 CPU，七轮交替顺序，保存 QPC 和线程周期。接纳路径包含真实核心的描述符消费和 recycle 发布，停止路径保持实际拒绝逻辑。不是纯 memset 基准，也不是内核 CPU、真实负载吞吐或延迟。

定向验证的一次结果如下，单位为 ns/发送调用；原始证据为 `out/sys-send-init/dc72ac18a1c0/evidence.json`：

| 发送及回收 | 1 | 101.36 | 91.52 |
| 发送及回收 | 8 | 272.74 | 273.18 |
| 发送及回收 | 32 | 928.15 | 930.31 |
| 停止拒绝 | 1 | 33.49 | 25.01 |

单包和停止拒绝可见常量成本下降；较大接纳批次没有稳定加速证据，寻址成本及测量波动均须保留。此次收益是去掉确定存在、且不参与正确性的固定清零工作，不宣称所有路径都加速或整体 VPN CPU 降低。宿主 Send 的两次 memset 在当前汇编中消失；数组本身仍占用调用栈。
