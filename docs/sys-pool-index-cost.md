# SYS 槽池的稀疏空闲扫描

起始源码指纹为 `eabc3c674a791a391f1bce3af952f02d3a5941f2e52dac0282214620dc8546ee`，完整快照保存在 `out/sys-pool-index-baseline/eabc3c674a79`。

## 问题与范围

发送路径在 TxLock 内调用 `PbPoolReserve`。此前的满池缓存只避免同一个锁窗口内反复确认满池；只要仍有一个可用槽，每次成功预留仍可能扫描全部槽。例如容量 512、仅最后一槽反复归还时，Next 每次回到零，每个包都检查 512 个槽状态。满池的新窗口也仍要重新扫描。

这次修改共享核心的私有池分配器，嵌入 64 字节空闲位图，保留原有逐槽代次和状态作为所有权依据。没有新增堆分配、线程、共享内存字段、导出接口表或数据 ABI 变化。

## 分配和所有权

- Next 直接可用时保留直接命中路径；否则按 Next 起点依次搜索位图当前字的高位、后续字、回绕后的字及起始字的低位，使用位扫描选择下一空闲槽。非二次幂容量的尾位初始化为零。1 至 512 的原有容量均支持，分配顺序和 Next 归一化保持一致。
- 搜索最多检查 17 个 32 位字；检查候选槽的真实状态，遇到忙槽或越界候选返回 CORRUPT，不因索引位而覆盖真实所有权。代次耗尽仍永久退役，不回绕至零；若许多空闲槽同时代次耗尽，一次搜索仍可能逐一退役这些候选，最多处理原有的 512 槽。这不是不受条件限制的恒定时间分配。
- 所有实际分配、回收、取消和完成通过核心预留/转换函数同步维护位图。位图位来自私有状态，不能由共享 token 直接授权；epoch、queue、slot、generation 和状态校验保留。
- DLL 接收内核发送描述符时，以前直接写镜像槽。现由 `PbPoolImport` 在整批检查作用域、较新代次、空闲状态及重复槽后统一提交；任意失败保持整批状态、代次和索引不变。描述符长度、偏移和格式仍先由原来的校验函数检查。
- DLL 故障后清退 Published 仍先要求无用户 lease、真实 QUERY 确认 STOPPED 且无原生引用，再通过带 token 校验的状态转换释放记账。错误不会被直接状态写入掩盖。退出仍依赖原有 Device Close、worker join、AllReturned 和 Returns rundown 屏障。

池仍由原有队列所有者串行访问：SYS 使用 TxLock，DLL 使用队列所有权/DataGate，最终清退取得 DataGate 排他锁。没有新增原子位操作或锁，也没有修改 worker 的等待、arm/recheck、批次数/字节预算或唤醒规则。

## 证据与取舍

`verify-sys-pool-index.ps1` 在冻结/当前核心的副本中，仅在真实槽状态检查和搜索字读取处插入计数，配合同一独立顺序模型运行。512 槽、连续 2000 次查询的结果：

| 场景 | 旧槽状态检查 | 新槽状态检查 | 新搜索字读取 |
| --- | ---: | ---: | ---: |
| 仅最后一槽可用，反复预留/归还 | 1,024,000 | 4,000 | 32,000 |
| 完全占用 | 1,024,000 | 2,000 | 32,000 |

这些数不计索引维护读写或代次检查，不代表内核 CPU 时间。分离的无插桩宿主基准覆盖直接命中、满池、单一空闲及奇数容量，以固定允许 CPU 进行七轮交替测量，保存全部样本和中位数。直接命中会增加索引维护成本；验收记录保留这个成本，不将所有场景描述为加速。实际驱动收益与池占用、批处理、数据复制及调度有关，仍需 ETW/WPA 验证。

## 回归与复现

- `pool_index_tests.c` 使用生产核心，遍历全部 512 种容量和 131,328 个“仅一个空闲槽”的顺序回合；校对返回 token 全部字段、Next、全部槽状态/代次及每个索引位。另有 260,000 次混合操作/模型核对、乱序释放、旧 token、整池代次耗尽、非二次幂尾部及损坏候选测试；池对象和槽数组后接保护页。
- 镜像批次覆盖重复、忙槽、错误作用域、旧/零代次、无效长度、部分有效后遇错的整批回滚，以及最大代次的导入、释放与退役。
- 发送窗口、回收有效前缀后故障、用户 lease、原生引用、仅内核发现故障时的 Published 清退、异步关闭和实际回调尾部等既有回归继续执行。测试夹具改用真实预留/发布建立满池，不再绕过核心直接改槽状态。
- Tests/Safety 纳入新的保护页模型；完整离线验收纳入池 A/B 和基准。源码冻结后才运行最终验收；驱动静态分析不通过新增告警抑制来消除问题。
