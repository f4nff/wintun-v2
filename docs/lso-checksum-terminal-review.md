# LSO 校验和配置与 32 包停机复核（2.0.0）

## 确认的生产问题

`common/offload_policy.c` 曾要求普通 TX IP/TCP 校验和配置同时开启，才保留
LSO。实际 `OID_TCP_OFFLOAD_PARAMETERS` 可以关闭普通校验和，同时保持或
启用 LSO。这时驱动错误地报告 LSO 不可用，并拒绝原本合法的 LSO 请求。

Microsoft 的[校验和卸载说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/offloading-checksum-tasks)
明确要求：普通校验和关闭后，只要 LSO 仍开启，LSO 生成的分段仍须填写
校验和。这里区分设备必须支持的校验和能力与当前普通发送校验和配置。

修正仅解除 LSO4/LSO6 对当前普通校验和配置的两处依赖。会话、允许位、
请求位、封装及系统能力的交集继续控制 LSO；RX RSC/URO 的校验和验证
前提保持原样。USO 自身门控也保持原样。旧 Wintun 导出、ABI、统一 v2 SYS
及版本 2.0.0 不变。

## 先复现，再修正

`lso_checksum_policy_tests.c` 使用实际 OID/策略处理函数，分别在 NDIS
6.20、6.30、6.83、6.89 的 hosted 配置中关闭普通校验和、关闭/重开 LSO、
变更允许位。额外观察器直接读取实际报告的 `NDIS_OFFLOAD` StatusBuffer，
核对 LsoV2 大小、最少段数、封装及相关校验和字段，再交回原有报告检查。
独立真值表按三个门控及会话状态判断 LSO，不调用被测解析函数生成期望。
每进程 IPv4 检查 8212 项、IPv6 检查 1044 项。

`tun32_offload_send_tests.c` 分族构造 32 个真实 WDK checksum/LSO/USO OOB
请求，复用实际 Read/Describe/Send 及 LSO 完成函数。每 NBL 一个 NB，首个
160 字节 MDL 覆盖全部头部。TCP/UDP 普通校验和与 LSO 使用 NDIS 6.20；
USO 有不足 MSS 的末段，因此使用实际宣告该能力的 6.84 配置。源 MDL
只读，原始 NBL/NB 在单次完成回调中实际释放；源页另外保留到验证及回收
结束。核对描述符、分段载荷/校验和、选项、TCP Timestamp 及统计字节数。

修正前的原始完整策略文件被冻结，独立编译为非发布负对照：普通校验和
关闭而 LSO 请求仍在时，32 包全部被拒。该进程只在槽位、映射、引用及
句柄全部归还后以专用 139 退出。修正后必须一次 Push 提交 32 个描述符。
原实际 OID 复现的专用退出码为 140。历史失败日志保留原始源码指纹，不
改标为当前成功证据。

正常路径另覆盖起始策略拒绝及在原有 31 包预算边界完成策略切换后拒绝
最后一包。边界用例建模已完成的策略更新；实际 OID 行为由上一组验证。
Describe 对拒绝请求也可能执行一次完整输入复制，分类前缀复制单独计数，
因此不将“仅成功包复制”作为虚假的优化结论。GSO 的 32 个原始请求与其
产生的更多逻辑分段分别记录。

## 并发归还及停机边界

新增 `--tun32-terminal` 入口分别编译、运行 IPv4/IPv6，各覆盖 TCP/UDP、
收/发、回绕及两种最后归还顺序。四个实际公开调用线程先处理后 31 个
私有指针，再由第五个受控调用者归还第一个指针。覆盖最后一次真实唤醒
触发后进入终止门控，以及原生工作线程真实退出后再归还私有指针。

测试不在公开调用者仍运行时调用 End。每个用例都汇合全部公开调用线程；
终止后的私有接收缓冲区仍保留到 End，最后归还只推进一次本地游标。
终止后的发送不能重新 Reserve/Commit 或复制到原生会话。实际自动复位
事件保持原行为；等待代码见证不冒充操作系统调度器已经停驻的证明。

## 复制与协议边界

`packet_request_family32_tests.c` 直接包含完整实际 `common/packet.c`，在
其显式 memcpy 边界计数。升序、降序、交错的 32 个独立输出，31 个输出
加尾包重试、容量 0 后重试及输出 31 与输出 0 重叠分别测试。正常输入每
个输出头/载荷只复制一次；无效别名在复制前拒绝，源、计划、输出元数据
及哨兵保持不变。每进程 24 场景，包含经过检查的预热。

`test_route_family32.py` 分别测试 IPv4 LSRR/SSRR 与 IPv6 Routing Type 2、
Home Address Option 及组合。独立端点 oracle 检查伪首部校验和、完整
32 包与短容量 31 后仅重试末包。TCP Timestamp 原字节保留，不用于发送
截止时间、日志时钟或批量提交时间。

## 永久入口与证据边界

主测试包含分族路由用例；Safety 与 UnifiedTests 包含上述分族 C 模型及
终止入口。四个定向入口为：

- `tools/audit/verify-lso-checksum-policy.ps1`：实际 OID、编码报告及门控矩阵。
- `tools/audit/verify-tun32-offload-send.ps1`：24 进程、240 场景，包含安全清理
  后退出的历史策略负对照。
- `tools/audit/verify-packet-request-family32.ps1`：8 进程、192 场景。
- `tools/audit/verify-tun32-dll-family.ps1 -IncludeTerminal32`：24 进程、768 场景，
  其中终止组 8 进程、256 场景、1280 次实际公开调用者线程汇合。

ISO/MS volatile 与普通/守护内存组合均分别检查。精确策略变更账本绑定原
文件及修正后文件的完整原始 SHA256，只接受该路径的两处分支修正；BOM、
UTF16、CRLF、其他路径或其他逻辑改动都不能借用此许可。其余依赖继续
逐字节检查，历史证据保留其原始源码与结果。

完整验收还暴露了旧 helper 终止测试的目录隔离缺口：负控在真实子进程
救援及汇合后直接退出 45，遗留的 `helper-PID-1` 可在 PID 重用时阻止下一
次测试创建目录。受控复现记录到调用错误 183、等待超时 258，且子进程
尚未创建；原先那次失败未记录 PID，不能据此追认其唯一原因。

测试 host 现在使用按进程创建标识隔离、原子独占的新父目录，并内建目录
碰撞、创建失败、边界及并发创建检查。正常结束必须删除空父目录；旧负控
的审计父进程根据本次明确输出的目录，仅清理已知文件及两层目录，拒绝
额外内容，不递归删除或处理历史目录。原超时、等待、终止及子进程汇合
断言保留，生产 helper 和旧 fixture 均不修改。

这些 hosted 场景核对内存、句柄、槽位、引用及实际测试线程的归还，不能
替代旧 Windows 实机、真实 NDIS/IRQL、Driver Verifier 或持续压力测试。
复制及批量操作计数也不能代替 CPU、吞吐与延迟实测。
