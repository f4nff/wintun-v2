# TUN 32 包的预算、停机与借用边界

版本保持 2.0.0，DLL/SYS 数值版本保持 2.0.0.0。本轮基线为
`f8745a1b269f1f6ad5097b5acc9c7806f27d720725a45baf2fd217dca0c5bd89`，
完整 636 文件快照在 `out/tun32-edge-baseline/f8745a1b269f`。
最终验收汇总在 `out/tun32-edge-investigation/final-review.json`。

## 自然发生的部分预留

旧接口的新测试先实际发布并由模拟原生端取走 `64-k` 个包，保留其完成，
使 64 个槽位只剩 k 个可预留。随后一次反序提交完整的 32 包前缀，覆盖
k=1/7/31、普通及字节 ring 回绕、继续收发及停止两条路径。

实际 Reserve(32) 只能返回 k，Commit(k) 全部接纳。没有完成释放新槽位时，
后缀 Reserve 返回 FULL/0，旧 ring Head 必须停在已接纳前缀；空调用次数
不作固定假设。原生端实际完成 `32-k` 个种子包后，恢复路径一次预留和
提交余下 `32-k`，目标载荷总共复制 32 次。停止路径只复制先前的 k 次，
后缀不再复制或提交。计数不包括建立初始压力时的包。

合法配置满足 ringCapacity >= slotCount，未完成槽位与 ring 占用互相制约。
因此不能在已有预留槽位之外再填虚假描述符，把 running Commit/Release
的 FULL 当作普通流量缺陷。旧有防御性短前缀测试继续保留，新测试则使用
真实池状态、完成、代数复用、公开 End 和已有私有回收屏障。等待计数只
表明到达等待代码段，不宣称线程已经停在内核等待对象上。

## SYS 发送字节预算

实际 Read → Describe → Send 路径按以太帧长度收费，每次尝试封顶 65536
字节，单窗口预算为 128 KiB。新增 32 包测试覆盖 IPv4/IPv6 TCP/UDP、
单 NBL 的 32 个 NB 及 32 个独立 NBL，以及宿主 NDIS 6.20/6.89 分支。

| 每包 IP 长度 | 每次预算收费 | 32 包的实际发布向量 |
| --- | --- | --- |
| 4082 | 4096 | 32 |
| 4083 | 4097 | 31, 1 |
| 65535 | 65536 | 16 次各 2 个 |

每个已发布包恰好有一次完整 IP 复制，另有 59 字节分类读取；两者分别
计数，元数据和测试构造复制不算载荷复制。在 31 包窗口自然释放时，原宿主
分别执行暂停、移除会话引用、故障，下一包在准入检查中停止，不再读取、
预留、Describe 或复制。先前的 31 个描述符仍保持完整并由实际 recycle
归还。单 NBL 的最终失败状态可以与此前已发布的前缀并存；驱动在这次 Send
中不重放该前缀。提交完成不等于已经发送到网络。每次原始 Send 只有一次完成
上调，不因窗口拆分增加。该测试不宣称最大 IP 包已通过真实网络 MTU。

## SYS 合并缓冲区与停机回收

32 × 32768 字节的有效包自然跨过 512 KiB 接收预算，每轮取 16 个。
65535 字节合并上限使每个合并对象只能容纳一对包，两个真实私有合并缓冲区
先被占满，因此首轮产生 14 个 NBL。只通过实际 NBL 归还释放缓冲区；
第二轮前归还 0/1/2 个合并对象时，第二轮分别产生 16/15/14 个 NBL。
部分 MDL 必须保持引用对应共享载荷，合并对象则保持私有缓冲区所有权。

首轮快照复制为 196608 字节：两个组各快照三个 32768 字节包，其中第三包
因合并容量不足成为边界。第二轮前归还一个或两个合并对象时，总快照量为
294912 或 393216 字节。该额外前瞻属于当前共享区隔离及合并校验路径，
不能据此删除私有快照或跳过报文校验；它与普通包无整包复制路径分别记录。

另在首轮后开始 Drain，验证第二批只得到停止完成，不能生成新 NBL 或快照。
故障场景交换最后一个 Active 借用与实际 worker 的静止见证次序，验证两者
均完成后才能停止。每个测试线程均核对实际退出并汇合，NBL/MDL、credit、
引用、合并 Busy 和句柄全部归还后才清理宿主。RSC 使用 6.30、URO 使用
6.89 能力变量，并拒绝访问该版本不存在的 OOB 元数据；这不是旧内核真实
布局或实机运行验证。

## Rust 输出前缀与停止后的借用

32 段 TCP/UDP IPv4/IPv6 输出分别在第 0/1/31 个缓冲区缺少容量。checked
FFI 必须只写完整前缀，保留未生成缓冲区及源数据；补足容量后以接受数推进
first 并传入剩余输出，不能重写前缀或改为逐段调用。TLS 计数记录真实 C
调用、first/count/written 和源/最终输出地址，旧 unsized 入口仍被毒化。

另先持有 31 个预留槽再请求 32 个，自然只得到 1 个。停止后 Commit 返回
STOPPED/0，未提交的 Vec 仍持有 lease，Drop 必须实际 Cancel 并清空借用。
持有 GSO lease 时 PrepareClose(0) 按当前接口返回 BUSY，映射保持有效，
仍可读取及分段；最终归还后才能完成关闭。载荷中的 64 位标记保持为不透明
数据，TCP 的时间戳选项边界沿用上一轮测试，不引入包发送时钟。

## 验收与范围

本轮未确认新的生产缺陷，没有修改 SYS/DLL 或 Rust 生产实现。新增测试
补足真实压力、字节预算、合并缓冲区和停机交错，版本和系统能力选择保持
不变。原 SYS 32 包审计的四个投影验证函数逐字移入共享审计文件，由原审计
及新预算审计复用，避免两份验证逻辑分化；AST 原文对照和原回归继续执行。

NDEBUG、ISO/MS volatile、守护内存及失败编译对照用于约束测试入口。守护
范围按宿主支持的分配记录；锁、NDIS 上调和部分内核对象仍是 hosted 模型。
计数不能替代真实 CPU、吞吐、IRQL、Driver Verifier 或目标系统长期泄漏
验收。完整离线构建、原定向回归、PE 导入/导出及固定版本检查由最终指纹
重新执行，历史证据保留各自原来的指纹。
