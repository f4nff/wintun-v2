# SYS 校验和累加循环

起始源码指纹为 `f32d9edfaf9f13a7d16515517ddbd6ee9d0aaa9c39141ecbffe9abb76ecb7420`，快照位于 `out/sys-checksum-baseline/f32d9edfaf9f`。

## 问题与修正

SYS 的 TCP/UDP 校验和生成、接收合并资格检查和 TCP 合并收尾都使用 `PbChecksumAdd`。原实现和实际 x64 SYS 指令每次循环只读取、累加一个网络序 16 位字；长包需要执行数万次循环控制。

当前每次主循环处理四个字、共八个字节，剩余的完整字和最后一个奇数字节沿用原规则。仍逐字节读取，不引入未对齐宽读、SIMD、CPU 特性判断或平台专用路径。四个字的和最多为 `4 * 65535`，使用无符号 32 位表达式；加入调用方 seed 后的模 `2^32` 结果与旧实现完全相同。保留原始未折叠和，不只保证最终 16 位校验和等价。

长输入循环次数从 `floor(N/2)` 降为 `floor(N/8) + floor((N%8)/2)`。65535 字节输入从 32767 次降为 8194 次，奇数末字节仍仅访问一次。所有读取均有实际剩余长度保护，没有读取、改写输入范围之外的字节。

这会影响 SYS 和 DLL 共用核心，因此回归同时覆盖普通包、LSO/USO 计划及校验和、TCP/UDP 合并字节与 NDIS 元数据。没有改变解析、包资格判断、所有权、锁、处理字节预算、事件、等待或清理逻辑。

## 可复现验证与成本边界

`checksum_tests.c` 的独立 oracle 逐字节累加到 64 位后截为 32 位，比较精确原始和及独立折叠值。覆盖每个 0..1024 长度、四种字节模式、七种 seed、MTU/32KiB/64KiB/128KiB 边界至 1MiB、16 种对齐、真实溢出、偶数边界连续累加及奇数末字节。输入受只读页和首尾保护页约束；空输入允许空指针。该测试加入普通和 Safety 入口。

`verify-sys-checksum.ps1` 分别链接冻结/当前 packet 核心，执行上述测试及实际 Describe、合并帮助函数和保护页 ReceiveBatch/归还/worker/QUERY。既有完整验收继续覆盖资源失败回滚、同步归还、故障见证、满 credit/完成环、暂停、有限排空及回调尾部等待。

宿主 benchmark 使用相同允许 CPU、相同输入、volatile 间接调用和七轮交替顺序，记录原始样本、结果、调用次数、周期和时间。它分别展示 0..7 字节等短输入与长输入，不把局部循环优化写成全部输入都更快：短输入多一次分支，可能有不足数个周期的额外成本。长输入循环控制减少的收益必须结合真实包尺寸分布评估。时间不作为 CI 通过阈值。

宿主计时不是内核 CPU、吞吐或延迟结果。SYS 未加载；真实 IRQL、Verifier、ETW/WPA、低资源及长稳仍需内核验收。实际 x64 SYS 还需核对生成指令，确认分组读取和余数边界没有被编译成越界宽读。
